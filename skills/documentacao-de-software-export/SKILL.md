# Integrated Documentation — Navigable HTML Export

> **Goal:** Generate a static, navigable, self-contained HTML site that consolidates all project documentation (requirements, ER diagrams, database metadata, API descriptions) into a single interface with cross-traceability between artifacts.

## 0. Prerequisites (Blocking)

Before initiating any operation, the agent **must** validate:

| Prerequisite                                  | Validation                                                                                              | Action on failure                                                                                |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `documentacao/` directory exists              | `documentacao/` accessible                                                                             | **Stop** — inform that the `documentacao-de-software` skill must be executed first               |
| `documentacao/README.md` exists and has content | Non-empty file, with `## Navigable Index` section                                                      | **Stop** — README is required to generate index.html                                             |
| At least 1 `req-XXXX` artifact exists         | Glob `documentacao/processo_unificado/artefatos_aprovados/detalhamento_requisitos/req-*.md` returns ≥1  | **Stop** — no requirements to export                                                             |
| Python 3.10+ available                        | `python --version` or `python3 --version`                                                              | **Stop** — install Python before proceeding                                                      |
| Python libraries installed                    | `pip install pyyaml jinja2 markdown`                                                                   | **Install automatically** if the user authorizes                                                  |

## 0.A. Mandatory Language (Blocking)

All content generated by this skill **MUST** be written in **Brazilian Portuguese (pt-BR)**. This includes:

- **HTML output**: page titles, navigation labels, section headers, metadata labels, footer text, and all user-facing text in the generated site.
- **Manifest and traceability data**: section names, gap descriptions, and summary labels.
- **Error and progress messages**: console output shown to the user during generation.

Only the SKILL.md, internal scripts (docstrings, comments), and configuration files are written in English. The purpose is to deliver documentation accessible to non-technical stakeholders in Brazil.

## 2. Mandatory Workflow

### Phase 1 — Scanning and Manifest

Run the `scripts/doc_scanner.py` script:

```bash
python skills/documentacao-de-software-export/scripts/doc_scanner.py \
  --input documentacao/ \
  --output documentacao_html/.build/manifest.yaml \
  --project-name "My Project Name"
```

> **Note:** The `--project-name` parameter is optional. If not provided, the script extracts the project name from the first heading in `README.md`. If no heading is found, it uses the directory name.

**What the script does:**

1. Recursively scans `documentacao/` and identifies all `.md` files by prefix/pattern.
2. Extracts metadata from each file (title, version, author, status, date) from the YAML header or markdown table.
3. Extracts cross-references (links `[...](...)`, mentions of `req-XXXX`, `RF-XXXX`, `RN-XXXX`, `api-`, `der-`, `did-`).
4. Classifies each file into a sidebar section according to the table in section 1.
5. Generates `manifest.yaml` with the complete navigation structure, including `project_name`.

**Post-execution validation:** The agent must verify that `manifest.yaml` was generated and contains at least 1 artifact of each type found.

### Phase 2 — Cross-Traceability Construction

Run the `scripts/trace_builder.py` script:

```bash
python skills/documentacao-de-software-export/scripts/trace_builder.py \
  --manifest documentacao_html/.build/manifest.yaml \
  --input documentacao/ \
  --output documentacao_html/.build/traceability.json
```

**What the script does:**

1. For each artifact, maps **backward traceability** (origin: which requirement/parent generated it).
2. For each artifact, maps **forward traceability** (derivatives: which tables, endpoints, tests stem from it).
3. Detects **gaps** (referenced but non-existent artifacts, orphaned RF/RN, broken references).
4. Generates `traceability.json` with the complete connection map.

**Post-execution validation:** The agent must:

- List gaps found and ask the user whether to fix or ignore them.
- If critical broken references exist (e.g., `req-XXXX` referenced but does not exist), **block** until resolution.

### Phase 3 — HTML Generation

Run the `scripts/html_generator.py` script:

```bash
python skills/documentacao-de-software-export/scripts/html_generator.py \
  --manifest documentacao_html/.build/manifest.yaml \
  --traceability documentacao_html/.build/traceability.json \
  --input documentacao/ \
  --output documentacao_html/ \
  --css skills/documentacao-de-software-export/assets/css/integrated-theme.css
```

**What the script does:**

1. Reads `manifest.yaml` for navigation structure.
2. Reads `traceability.json` to enrich pages with traceability links.
3. Converts each `.md` to HTML using `markdown` with extensions (tables, fenced_code, toc, admonition).
4. Renders inline Mermaid diagrams (via `<script src="mermaid.js">` in the browser).
5. Generates `index.html` from the documentation `README.md`.
6. Generates navigation page with topbar and collapsible sidebar menu.
7. Creates a detailed page for each artifact with type badges, traceability links, and up/down/side navigation.
8. Copies `integrated-theme.css` to the output directory.
9. Creates `nav.json` file for dynamic navigation via JavaScript.

### Phase 4 — Validation and Delivery

1. Open `index.html` in the browser and validate:
   - Sidebar menu works and lists all sections.
   - Navigation links between pages work.
   - Mermaid diagrams render correctly.
   - Traceability badges appear on artifacts.
   - CSS `integrated-theme.css` is applied.
2. Validate that `nav.json` reflects the actual file structure.
3. Validate that the traceability matrix (`traceability/matrix.html`) is complete.
4. Inform the user of the output directory path and how to view (open `index.html` in the browser).

| Script                      | Responsibility                                                                     | Lines (ref) |
| --------------------------- | ---------------------------------------------------------------------------------- | ----------- |
| `scripts/doc_scanner.py`    | Scans `documentacao/`, extracts metadata, generates `manifest.yaml`                | ~300        |

**Python Dependencies:** `pyyaml`, `jinja2`, `markdown` (with extensions: `tables`, `fenced_code`, `toc`, `admonition`, `meta`).

## 4. Generation Rules

### 4.1 Markdown Conversion

- Use `markdown` library with extensions: `tables`, `fenced_code`, `toc`, `admonition`, `meta`.
- `mermaid` blocks must remain as `<div class="mermaid">` for browser rendering via Mermaid.js CDN.
- Tables must inherit styles from the CSS (`trace-matrix`, `doc-badge`, etc.).

### 4.2 Traceability

- Each artifact page must contain a **traceability box** (`.traceability-box`) at the end with:
  - **Origin:** link to parent artifact (e.g., `req-0001` for `tec-req-0001`).
  - **Derivatives:** links to child artifacts (tables, endpoints, tests).
  - **Status:** visual indicator (ok/pending/missing) per `traceability.json`.

### 4.3 Navigation

- **Topbar:** project title + search bar (text filter on nav.json).
- **Sidebar:** collapsible sections organized by artifact type with **blue background** (`--sidebar-bg: #0047ab`). The project name appears in the sidebar header as a clickable link that navigates back to `index.html`.
- **Inter-page navigation:** previous/next links in the footer of each page.
- **Breadcrumb:** navigation path at the top of each page.

### 4.4 Mermaid.js

- Include Mermaid.js via CDN: `<script src="https://cdn.jsdelivr.net/npm/mermaid/dist/mermaid.min.js"></script>`.
- Initialize with `mermaid.initialize({startOnLoad: true, theme: 'default'})`.
- Mermaid blocks in Markdown must be converted to `<div class="mermaid">...</div>`.

### 4.5 CSS

- Use exclusively the existing `integrated-theme.css` in `assets/css/`.
- Do not add inline CSS or additional CSS files.
- The CSS defines colors, badges (`.doc-badge-req`, `.doc-badge-api`, `.doc-badge-dados`), traceability boxes, and tables.

## 5. Automated Validations (Smoke test script)

After generation, run `scripts/validate_output.py`:

```bash
python skills/documentacao-de-software-export/scripts/validate_output.py \
  --site documentacao_html/
```

Checks:

- [ ] `index.html` exists and references `css/integrated-theme.css`
- [ ] `nav.json` exists and is valid JSON
- [ ] Each original `.md` file has a corresponding `.html` in the output
- [ ] All internal links in HTML point to existing files
- [ ] No empty `<div class="mermaid">` tags
- [ ] `traceability/matrix.html` exists

## 7. Re-generation

When documentation is updated (new requirements, content changes):

1. Re-run Phase 1 (scanning) — regenerates `manifest.yaml`.
2. Re-run Phase 2 (traceability) — regenerates `traceability.json`.
3. Re-run Phase 3 (HTML generation) — overwrites `documentacao_html/`.
4. Run Phase 4 (validation).
5. Run Phase 5 (cleanup).

**No manual execution required** — the skill detects changes and re-runs automatically if the user invokes with "export again" or similar.

## 8. Final Cleanup

After the site is successfully generated and validated, the agent **must** perform a cleanup step:

- **Delete the intermediate build directory:** `rm -rf documentacao_html/.build`
- This ensures the final deliverable is clean and contains only the static site files.

This step should only be executed after confirming the site works as expected.


## 7. Output Format

The generated site is **static** (HTML + CSS + JS), no server required. It can be:

- Opened locally in the browser (`file:///...`).
- Hosted on GitHub Pages, Netlify, Vercel or similar.
- Packaged as ZIP for distribution.

## 8. Known Limitations

| Limitation                      | Impact                           | Mitigation                                                                |
| ------------------------------- | -------------------------------- | ------------------------------------------------------------------------- |
| Mermaid.js requires CDN (internet) | Diagrams do not render offline | Fallback: convert Mermaid to static SVG via `mmdc` if available          |
| Very large files (>10MB)        | Render performance              | Split into multiple pages with pagination                                 |
| Mermaid with invalid syntax     | Diagram does not render         | Mermaid syntax validation script before generation                        |
| Images (wireframe PNGs)         | Not converted to HTML           | Copy images to `documentacao_html/assets/img/` and reference via `<img>`  |
